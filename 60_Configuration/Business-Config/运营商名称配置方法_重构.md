# 运营商名称配置方法

## 阅读入口

- 先看“使用边界”和“配置入口速查”，确认当前问题属于状态栏、锁屏、SIM 卡名称、手动搜网列表还是 VoWiFi / Cross-SIM 名称。
- 真正修改配置前，先按平台进入 UNISOC / MTK / QCOM 对应小节；不要把 APN、carrier id 或 MVNO 匹配表当成运营商名称显示入口。
- 排查显示异常时，结论要同时写清来源链路、命中的配置文件、设备侧产物和 `dumpsys carrier_config` / RIL / modem 侧证据。

## 使用边界

这篇只整理运营商名称的可复用配置方法。排查时先分清显示面，因为“状态栏名称”“锁屏名称”“SIM 卡名称”“手动搜网列表名称”“VoWiFi / Cross-SIM 名称”不是同一条链路。

运营商名称通常来自这些来源：

| 来源 | 典型字段 / 文件 | 主要影响 |
|---|---|---|
| SIM EF | `EF_SPN`、`EF_PNN`、`EF_OPL`、`EF_SPDI`、`EHPLMN` | SIM 名称、SPN/PLMN 显示规则、EONS 名称 |
| 网络 / modem | NITZ、ONS/EONS、RIL `alphaLong` / `alphaShort`、`ServiceState.operatorAlpha` | 当前注册网络名称、手动搜网列表、CellInfo 名称 |
| 本地 PLMN 表 | UNISOC `numeric_operator.xml`、MTK/QCOM `spn-conf.xml`、QCRIL static ONS table | SIM / 网络侧名称缺失后的 fallback |
| CarrierConfig | `carrier_name_override_bool`、`carrier_name_string`、`pnn_override_string_array`、`opl_override_string_array`、`spdi_override_string_array` | 状态栏 / 锁屏 / SIM 显示策略的 AP 侧覆盖 |
| UI 策略 | `updateCarrierDisplayName`、`updateSpnDisplayLegacy`、WFC / Cross-SIM 格式化 key | 飞行模式、无服务、VoWiFi、Cross-SIM 这类显示格式 |

不要把 `carrier_list.textpb`、APN 的 `mvno_type` / `mvno_match_data` 当成运营商名称配置入口。前者用于 carrier id 识别，后者用于 APN 匹配，都不能直接决定 UI 应显示哪个运营商品牌。

## Android 通用显示链路

### 状态栏 / 锁屏

AOSP common 的入口是 `ServiceStateTracker.updateCarrierDisplayName()`：

```text
updateCarrierDisplayName()
-> enable_carrier_display_name_resolver_bool ?
       CarrierDisplayNameResolver.getCarrierDisplayNameData()
     : getCarrierDisplayNameLegacy()
-> setCarrierName()
-> notifyCarrierDisplayNameDataChanged()
```

`enable_carrier_display_name_resolver_bool` 默认是 `false`，所以多数分支默认走 legacy。legacy 下 `getServiceProviderName()` 的关键顺序是：

```text
brand override
-> 如果 carrier_name_override_bool=true，返回 carrier_name_string
-> 如果 SIM EF_SPN 为空，返回 carrier_name_string
-> 否则返回 SIM EF_SPN
```

因此：

- 只写 `carrier_name_string` 不等于强制改名。
- 要强制状态栏 / 锁屏显示目标名称，必须配置 `carrier_name_override_bool=true` 加 `carrier_name_string`。
- 如果 `carrier_name_override_bool=false`，`carrier_name_string` 只是 SPN 为空时的低优先级兜底。

当 CDNR 打开时，`CarrierDisplayNameResolver` 的 EF 来源优先级是：

```text
Carrier API
> CarrierConfig
> ERI
> USIM
> SIM
> CSIM
> RUIM
> voice operator signalling
> data operator signalling
> modem config
```

CarrierConfig 在 CDNR 中不只提供 `carrier_name_string`，还可以通过 `spdi_override_string_array`、`pnn_override_string_array`、`opl_override_string_array`、`ehplmn_override_string_array` 改变类似 SIM EF 的显示规则。

### 手动搜网列表名称

手动搜网列表不是简单读取状态栏名称。它通常来自 modem/RIL 的 available network 或 network scan 结果，核心字段是：

```text
alphaLong
alphaShort
operatorNumeric
status
ACT / RAT
```

一般链路是：

```text
modem 扫描 PLMN / RAT
-> RIL / vendor telephony 生成 OperatorInfo 或 NetworkInfo
-> 如 alphaLong/alphaShort 为空或等于 numeric，平台可能再查 SIM EONS / NITZ / 本地表
-> Settings / NetworkSelect UI 显示 long name，必要时回退 short name 或 MCCMNC
-> UI 再追加 2G/3G/4G、Forbidden、Unknown 等状态
```

所以手动搜网列表名称不对时，不要先改 `carrier_name_string`。正确证据顺序是：

1. 看 RIL / framework 收到的 scan result 里 `alphaLong`、`alphaShort`、`operatorNumeric` 是什么。
2. 看平台是否在 AP 侧对 scan result 又调用了 operator name resolver。
3. 如果最终显示 MCCMNC，再看本地 PLMN 表 key 是否命中，尤其是 2 位 / 3 位 MNC 补零。
4. 如果最终显示 SIM PNN/OPL 名称，再看当前 RAT、LAC/TAC、OPL / OPL5G 是否允许命中。

常用 log 关键字：

```text
UNSOL_NETWORK_SCAN_RESULT
RIL_REQUEST_QUERY_AVAILABLE_NETWORKS
OperatorInfo
alphaLong
alphaShort
operatorNumeric
NetworkSelectSettings
CellInfoList display
mAlphaLong
mAlphaShort
```

平台差异：

| 平台 | 手动搜网列表名称链路 |
|---|---|
| UNISOC | `RadioIndication.updateNetworkList()` 调 `UniOperatorNameHandler.updateNetworkList()`，再用 `getHighPriorityPlmn()` 查 SIM PNN/OPL、ONS、NITZ、`numeric_operator.xml`。命中后替换原始 operator name，并按 ACT 追加 `2G/3G/4G`。 |
| MTK | `MtkRIL.lookupOperatorNameForPlmnList()` 使用 `DISPLAY_TS25 | DISPLAY_EONS | DISPLAY_NITZ` 规则；`MtkRadioExNetworkResponse` 在 PLMN 名为空或格式要求查名时会调用 `lookupOperatorName()`。 |
| QCOM | `AvailableNetworks.cpp` 把 `RilGetAvailNetworkResult_t.info` 复制成 `RIL_OperatorInfo` 的 `alphaLong` / `alphaShort` / `operatorNumeric` / `status`；名称主要来自 modem / QCRIL，而不是 AP CarrierConfig。QCRIL 可在 modem EONS 为空时查 `qcril_qmi_ons_memory_list`。 |

### 代码加载逻辑

`UniOperatorNameHandler` 在 `UniTelephonyGlobals` 初始化，服务名是 `ions_ex`。本地表路径写死为：

```text
Environment.getProductDirectory() + "/etc/numeric_operator.xml"
```

`getHighPriorityPlmn(phoneId, operatorNumeric, lac)` 的核心顺序：

```text
1. 校验 phoneId 和 operatorNumeric，operatorNumeric 必须是 5 或 6 位数字
2. 如果 config_is_nitz_higher_priority_bool=true 且 NITZ 有效，优先返回 NITZ
3. 查 operator_name_ignore_rules，命中特殊规则时直接返回定制名
4. 查 PNN / OPL：
   - lac=-1 时先从 IccRecords 取当前 LAC
   - NR 且 EF_OPL5G 可用时走 OPL5G / PNN
   - 否则走普通 OPL / PNN
   - 没有 OPL 但注册 HPLMN 时可取 PNN 第一条
5. 查 ONS：
   - 仅在未配置 ignore ONS
   - 且 operatorNumeric 是 HPLMN
   - 且当前 camping network 等于 operatorNumeric
6. 查 NITZ：
   - 属性格式为 persist.vendor.radio.nitz.info.simX=mccmnc=long=short
   - NITZ 还会经过 invalid_nitz_list 过滤
7. 查 product/etc/numeric_operator.xml
   - 先查缓存
   - 缓存未命中再解析 string-array item
   - 5 位且第 4 位是 0 的 MCCMNC，会删除这个 0 后再查表
8. 仍未命中则返回空字符串
```

`updateNetworkList(phoneId, operatorInfo)` 专门处理手动搜网列表：

```text
operatorInfo[0] = 原始 operatorName
operatorInfo[2] = "mccmnc act"
operatorInfo[3] = state
-> split 出 mccmnc
-> 调 getHighPriorityPlmn(phoneId, mccmnc, -1)
-> 命中则替换 operatorName
-> 去掉名称末尾已有的 2G/3G/4G
-> 按 ACT 0/1/2/7 追加 2G/3G/4G
-> UNKNOWN 时追加 unknownName
```

UNISOC 修改建议：

| 目标 | 优先改法 |
|---|---|
| 本地 PLMN fallback 错 | 改 `numeric_operator.xml` |
| 手动搜网列表显示 MCCMNC | 先看 `updateNetworkList` 是否调用 `getHighPriorityPlmn`，再看 `numeric_operator.xml` key 是否命中 |
| 手动搜网列表显示 SIM PNN/OPL 名称不符合预期 | 先查 EF_PNN / EF_OPL / EF_OPL5G、当前 RAT、LAC/TAC，不要直接改本地 XML |
| 状态栏 / 锁屏要强制某名称 | 改 CarrierConfig，配置 `carrier_name_override_bool=true` 和 `carrier_name_string` |
| 同一 PLMN 在 product/vendor/system 名称不一致 | 先用 log 确认当前代码读哪份，再统一有效来源 |

### 代码加载逻辑

`MtkSpnOverride` 是 MTK 运营商名本地表的核心类，单例初始化时会加载：

```text
loadSpnOverrides()
loadVirtualSpnOverridesByEfSpn()
loadVirtualSpnOverridesByImsi()
loadVirtualSpnOverridesByEfPnn()
loadVirtualSpnOverridesByEfGid1()
```

普通 `spn-conf.xml` 读取顺序：

```text
如果 persist.vendor.operator.optr=OP09：
    先读 /vendor/etc/spn-conf-op09.xml
    不存在再读 /system_ext/etc/spn-conf.xml
否则：
    读 /system_ext/etc/spn-conf.xml

如果 /oem/telephony/spn-conf.xml 存在且时间戳更新：
    用 OEM 文件覆盖 system_ext 文件
```

MVNO virtual SPN 读取位置固定在 `/vendor/etc`。匹配顺序由 `getSpnByPattern()` 决定：

```text
EF_SPN
-> IMSI
-> EF_PNN
-> EF_GID1
```

`MtkRIL.lookupOperatorName()` 是网络名称解析入口，常见规则：

```text
DISPLAY_SPN  -> lookupOperatorSPN()
DISPLAY_EONS -> 如果 NR attached 先查 5G EONS，再查普通 EONS / CPHS ONS
DISPLAY_NITZ -> lookupOperatorNameNitz()
DISPLAY_TS25 -> lookupOperatorNameMVNO()
```

`lookupOperatorNameForPlmnList()` 用于手动搜网列表，默认规则是：

```text
DISPLAY_TS25 | DISPLAY_EONS | DISPLAY_NITZ
```

其中 TS25 / MVNO 最终会走 `MtkServiceStateTracker.lookupOperatorName()`：

```text
getSpnByPattern()
-> lookupCnSharingOperatorName()
-> getSpnByNumeric()
-> default numeric
```

`getSpnByNumeric()` 先查 MTK 内置 resource 中的常见运营商名，再 fallback 到 `spn-conf.xml` 中的 `spnOverride numeric/spn`。

MTK 修改建议：

| 目标 | 优先改法 |
|---|---|
| 普通 MCCMNC 名称 fallback 错 | 改 `device/mediatek/system/common/spn-conf.xml` |
| MVNO 独立品牌名 | 按可用识别条件改对应 `virtual-spn-conf-by-*` |
| OP09 项目名称不生效 | 先查 `/vendor/etc/spn-conf-op09.xml` 是否优先 |
| 手动搜网列表名称不符 | 看 `lookupOperatorNameForPlmnList()`、`MtkRIL.lookupOperatorName()`、`MtkSpnOverride` log |
| 状态栏 / 锁屏强制名称 | 改 CarrierConfig，避免污染全局 PLMN 表 |

### 手动搜网 / CellInfo 加载逻辑

QCOM 手动搜网名称主要在 QCRIL / modem 链路完成。

`AvailableNetworks.cpp` 把 `RilGetAvailNetworkResult_t.info` 转成 `RIL_OperatorInfo`：

```text
i.alphaLong      -> RIL_OperatorInfo.alphaLong
i.alphaShort     -> RIL_OperatorInfo.alphaShort
i.operatorNumeric -> RIL_OperatorInfo.operatorNumeric
i.status         -> RIL_OperatorInfo.status
```

QTI AIDL `OperatorInfo` 定义：

```text
alphaLong: Long alpha ONS or EONS
alphaShort: Short alpha ONS or EONS
operatorNumeric: 5 or 6 digit numeric code (MCC + MNC)
status: STATUS_UNKNOWN / AVAILABLE / CURRENT / FORBIDDEN
```

QCRIL fallback 表在 `qcril_qmi_nas2.cpp`：

```text
qcril_qmi_ons_memory_cn_list
qcril_qmi_ons_memory_tw_list
qcril_qmi_ons_memory_list
qcril_qmi_nas2_find_static_operator_name()
qcril_qmi_nas2_find_static_operator_name_internal()
```

内部查找规则：

```text
按 MCC / MNC 查 qcril_qmi_ons_memory_list
-> 如果表中是单 digit MNC，会补 0 后再比较
-> 命中返回 full_name_ptr / short_name_ptr
-> 未命中时 long_ons_ptr 回退到 mcc_mnc_str_ref，short_ons_ptr 为空
```

QCRIL 在 modem EONS 长短名为空或空白时，会尝试：

```text
NITZ persistent cache / shadow cache
-> qcril_qmi_nas2_find_static_operator_name()
-> MCCMNC fallback
```

因此 QCOM 手动搜网列表名称不对时，重点看 QCRIL 的 `alphaLong` / `alphaShort` 来源。CarrierConfig RRO 通常不会直接改变 `AvailableNetworks.cpp` 上报给 framework 的 `RIL_OperatorInfo`。

QCOM 修改建议：

| 目标 | 优先改法 |
|---|---|
| 状态栏 / 锁屏强制显示某名称 | CarrierConfig RRO `vendor.xml` 或 `assets/carrier_config_*.xml` |
| 只在 SIM SPN 缺失时兜底 | 保持 `carrier_name_override_bool=false`，只配置 `carrier_name_string` |
| 手动搜网列表名称不符 | 查 QCRIL `alphaLong` / `alphaShort`、NITZ cache、`qcril_qmi_ons_memory_list` |
| 想改 `spn-conf.xml` | 先证明目标分支 AP framework 或 vendor framework 读取 `/system_ext/etc/spn-conf.xml` |
| QSSI / target RRO 不一致 | 先确认当前产品最终打包哪一份，必要时保持两侧一致 |

## 常见误区

| 现象 | 优先检查 | 不要误判为 |
|---|---|---|
| 改了 `numeric_operator.xml` 状态栏没变 | SIM EF / NITZ / CarrierConfig 是否更高优先级 | XML 没编进去 |
| 改了 `carrier_name_string` 没生效 | 是否缺 `carrier_name_override_bool=true`，或目标 CarrierConfig 未命中 | key 不支持 |
| 手动搜网列表不随 CarrierConfig 变化 | scan result 的 `alphaLong` / `alphaShort` 来源 | CarrierConfig RRO 没编进 |
| 改了 `spn-conf.xml` 没生效 | 当前平台是否真的读取该文件；QCOM 当前树尤其要确认 | XML 格式一定错 |
| MVNO 仍显示主网名 | 是否有可用 IMSI / GID1 / SPN / PNN / OPL 识别条件 | APN MVNO 字段没配 |
| 手动搜网列表显示 MCCMNC | `alphaLong` / `alphaShort` 是否为空，本地表 key 是否命中，MNC 位数是否正确 | 注册失败 |
| 漫游图标已消失但名称仍是 VPLMN | `non_roaming_operator_string_array` 只影响漫游判断，显示名仍看 SPN / PLMN 规则 | non-roaming 配置无效 |
| 飞行模式后名称变化 | radio off / out of service 是否清 NITZ 缓存或重新计算 fallback | NITZ 从未收到 |
| 同一 PLMN 多份 XML 名称不一致 | 当前代码到底读 `/product`、`/vendor`、`/system_ext` 哪份 | 随机加载 |

## 推荐处理流程

1. 先问清楚显示面：状态栏、锁屏、SIM 卡名、手动搜网列表、VoWiFi / Cross-SIM。
2. 先抓运行时来源：`gsm.operator.*`、`gsm.sim.operator.*`、`dumpsys carrier_config`、`telephony.registry`、radio log。
3. 如果是状态栏 / 锁屏，优先判断 SIM EF、NITZ、CarrierConfig 哪个优先级命中。
4. 如果是手动搜网列表，优先判断 RIL 上报的 `alphaLong` / `alphaShort` 和平台二次查名逻辑。
5. 只在证明当前来源是本地 fallback 时，才改 `numeric_operator.xml`、`spn-conf.xml` 或 QCRIL static ONS table。
6. 需要按单个 carrier 精准覆盖状态栏名时，优先 CarrierConfig，不要改全局 PLMN 表。
7. 修改后同时验证源文件、设备侧产物、运行时 dump、log 中最终名称。
