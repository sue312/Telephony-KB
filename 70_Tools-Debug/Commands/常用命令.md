# 常用命令

常用命令只沉淀取证方法和工程操作入口。业务判断、根因分析和配置结论回到对应流程、配置方法和案例文档。

## 速查结论

| 场景               | 优先命令                                                                  | 备注                                       |
| ---------------- | --------------------------------------------------------------------- | ---------------------------------------- |
| 注册、数据、通话失败       | `logcat` + `dumpsys phone` + `dumpsys telephony.registry` + modem log | `dumpsys` 是状态快照，不能替代 failure window 日志   |
| CarrierConfig 验证 | `adb shell cmd phone cc help`、`dumpsys carrier_config`                | `cmd phone cc` 受 Android 版本、权限和 subId 影响 |
| SIM / 运营商名问题     | `getprop`、`dumpsys isub`、`dumpsys carrier_config`                     | 先确认 SIM、subId、MCC/MNC、carrierId          |
| AP 状态同步问题        | `dumpsys telephony.registry`、`dumpsys phone`、radio log                | 对齐采集时间，避免只看最终状态                          |
| 工程修改排查           | `git status`、`git diff`、`repo status`                                 | destructive 命令执行前必须确认工作区可丢弃              |
| 源码 / 日志关键字定位   | `rg`、`rg --files`                                                       | 优先用 `rg` 缩小范围，再进入具体文件或 failure window |
| 抓包               | `tcpdump -i any -s 0 -w ...`                                          | 默认用普通可执行权限，避免不必要的 setuid/setgid          |

## 最小取证模板

问题复现前后至少保留时间点、AP log、核心 dumpsys 和 bugreport。modem log 按平台工具另行采集。

```powershell
adb devices
adb shell date
adb logcat -c

# 复现问题后采集
adb logcat -b main,system,radio -v threadtime > ap_radio.log
adb shell dumpsys phone > phone.txt
adb shell dumpsys telephony.registry > telephony_registry.txt
adb shell dumpsys isub > isub.txt
adb shell dumpsys carrier_config > carrier_config.txt
adb bugreport bugreport.zip
```

采集后先确认：

- `adb shell date` 时间和日志时间能对齐。
- `ap_radio.log` 覆盖了失败窗口。
- `dumpsys` 只代表采集时刻状态，不能反推完整过程。
- 需要定位注册、通话、数据失败时，仍要结合 modem log。

## 危险命令

| 命令                                                  | 风险           | 使用口径                            |
| --------------------------------------------------- | ------------ | ------------------------------- |
| `adb root`                                          | 改变设备权限环境     | 只用于 userdebug / eng 调试，记录执行前后状态 |
| `adb remount`                                       | 改变分区挂载状态     | 配置验证后要说明产物是否需要重新编译或刷机           |
| `adb reboot -p`                                     | 直接关机         | 只在需要验证冷启动或断电场景时使用               |
| `adb shell setenforce 0`                            | 放宽 SELinux   | 只能验证方向，不能作为最终结论                 |
| `repo sync -f`                                      | 可能覆盖本地修改     | 执行前先跑 `repo status`             |
| `repo forall -c 'git clean -df && git checkout -f'` | 删除未跟踪文件并丢弃修改 | 只适合确认可重置的编译环境                   |
| `git reset --hard`                                  | 丢弃本地修改       | 不作为常规排查命令                       |

## adb 命令

### 基础连接

```powershell
adb devices
adb wait-for-device
adb get-serialno
adb shell date
adb shell getprop
adb shell getprop ro.serialno
adb shell getprop | findstr /i "product serial"
```

### 权限和分区

```powershell
adb root
adb remount
adb shell lpdump -j
adb shell df -h
adb shell getenforce
adb shell setenforce 0
```

`setenforce 0` 只用于临时调试。验证后必须说明 SELinux 状态，否则结论容易被宽权限环境污染。

### 电源与重启

```powershell
adb reboot
adb reboot userspace
adb shell svc power reboot userspace
adb reboot -p
```

### logcat

```powershell
adb logcat -c
adb logcat -b main,system,radio -v threadtime > ap_radio.log
adb logcat -b radio -v threadtime > radio.log
adb logcat -s AndroidRuntime
adb logcat -v threadtime | findstr /i "RILJ ServiceStateTracker Ims Uicc CarrierConfig"
```

### bugreport

```powershell
adb bugreport bugreport.zip
```

### 文件导出

```powershell
adb pull /data/user_de/0/com.android.phone/files carrier_config_files
adb shell screencap -p /sdcard/screen.png
adb pull /sdcard/screen.png .
```

按业务需要再导出平台相关目录，例如音频参数、APN、CarrierConfig 或 modem 产物。不要把某个平台的私有路径默认当成通用路径。

### 常用状态

```powershell
adb shell dumpsys phone
adb shell dumpsys telephony.registry
adb shell dumpsys isub
adb shell dumpsys carrier_config
adb shell dumpsys ims
adb shell dumpsys telecom
adb shell dumpsys connectivity
adb shell dumpsys wifi
adb shell pm list features
```

### SIM / 网络属性

```powershell
adb shell getprop | findstr /i "gsm sim ril radio ims persist.vendor"
adb shell dumpsys carrier_config | findstr /i "phoneId subId mcc mnc carrierId specific"
adb shell dumpsys isub | findstr /i "subId slot icc mcc mnc carrier"
```

`service call phone` 这类 Binder 序号命令 Android 版本差异大，可读性差。优先用 `cmd phone`、`dumpsys phone`、`dumpsys telephony.registry`。

### CarrierConfig 临时覆盖

```powershell
adb shell cmd phone cc help
adb shell cmd phone cc get-value -s <subId>
adb shell cmd phone cc set-value -p carrier_volte_available_bool false
adb shell cmd phone cc clear-values
```

使用口径：

- 先跑 `adb shell cmd phone cc help` 确认当前 Android 版本支持的参数。
- `-s` 通常表示 `subId`，不要直接当成 slotId。
- 临时覆盖只用于验证方向，验证后必须执行 `clear-values`。
- 最终结论仍要用源码配置、运行时 `dumpsys carrier_config` 和业务日志一起确认。

### ADB over Wi-Fi


### 网络抓包

```powershell
adb root
adb push tcpdump /data/local/tmp/tcpdump
adb shell chmod 755 /data/local/tmp/tcpdump
adb shell /data/local/tmp/tcpdump -i any -p -s 0 -w /sdcard/netcap.pcap
adb pull /sdcard/netcap.pcap .
```

默认使用 `chmod 755`。只有明确知道为什么需要 setuid/setgid 时，才考虑更高权限。

## dumpsys 命令

### Telephony

```powershell
adb shell dumpsys phone
adb shell dumpsys telephony.registry
adb shell dumpsys isub
adb shell dumpsys carrier_config
```

### IMS / 通话

```powershell
adb shell dumpsys ims
adb shell dumpsys telecom
```

### Connectivity / Wi-Fi

```powershell
adb shell dumpsys connectivity
adb shell dumpsys wifi
adb shell dumpsys netpolicy
```

### 分析建议

- `dumpsys` 是状态快照，不是完整过程。
- 对注册、IMS、call failure，仍然需要 failure window 的 AP log 和 modem log。
- 保存 `dumpsys` 时记录采集时间，方便和 log 对齐。

## rg 命令

`rg` 适合在 Android 大仓、平台代码和导出日志里做第一轮关键字定位。优先用它缩小文件范围，再打开具体文件或回到对应 log 时间窗分析。

### 基础搜索

```bash
rg "CarrierConfig"
rg -n "ServiceStateTracker|updateServiceState" .
rg -i "attach reject|tau reject|emm cause|esm cause" <log-dir>
rg -F "mnc010.mcc602" .
```

### 搜文件名和限定类型

```bash
rg --files
rg --files -g "*.java" -g "*.kt" -g "*.xml" | rg "CarrierConfig|apns-conf|ecc"
rg --files | rg -i "carrier|apn|ecc|nv|mcfg"
```

### 上下文和范围控制

```bash
rg -n -C 3 "REGISTRATION_STATE|DATA_REGISTRATION_STATE" <path>
rg -n --glob "!out/**" --glob "!*.png" --glob "!*.zip" "keyword" .
rg -n --hidden --glob "!.git/**" "keyword" .
rg -l "keyword" <path>
```

使用口径：
- `-n` 显示行号，适合后续引用代码位置。
- `-i` 忽略大小写，适合搜 log、运营商字段和缩写。
- `-F` 按固定字符串搜索，适合包含 `.`、`[`、`]`、`+` 等正则特殊字符的关键字。
- `-C 3` 显示前后 3 行上下文；只想看前后单侧时用 `-A` / `-B`。
- `--files` 只列文件路径，适合先找候选文件，再对候选文件做内容搜索。
- 在 Android 大仓里不要从仓库根目录无脑搜所有内容；先用 `-g` / `--glob` 排除 `out/`、二进制、压缩包和图片。

PowerShell 中正则包含特殊字符时，优先用单引号包住搜索表达式；只是搜原文时直接加 `-F`。

## git 命令

### 本地查看与提交

```bash
git status .
git diff .
git log --oneline --decorate -n 20
git add <path>
git commit -m "message"
git commit --amend
```

### 分支与回退

```bash
git checkout -b <branch>
git checkout <branch>
git branch -a
git branch -D <branch>
git revert <commit-id>
git reset --soft HEAD^
git restore --staged <path>
```

`git reset --hard` 会丢弃本地修改，只有确认工作区可丢弃时再用。

### Gerrit 提交

```bash
git push origin HEAD:refs/for/<target-branch>
git push origin HEAD:refs/for/<target-branch>%topic=<topic>
```

### patch

```bash
git format-patch HEAD^
git diff > change.diff
git apply change.diff
git blame <path>
```

## repo 命令

### 初始化与同步

```bash
repo init -u <manifest-url> -b <branch> -m <manifest.xml>
repo init -u <manifest-url> -b <branch> -m <manifest.xml> --reference <mirror-path>
repo sync -c -f -j16
repo sync <project-name>
```

`repo sync -f` 可能覆盖未提交修改，执行前先看 `repo status`。

### 分支与状态

```bash
repo start <local-branch> --all
repo start <local-branch> <project-path>
repo branches
repo checkout <branch>
repo status
repo diff
repo info
repo abandon <branch>
```

### 批量操作与提交

```bash
repo forall -c 'git status --short'
repo forall -p -c 'git branch --show-current'
repo forall -c 'git clean -df && git checkout -f'
repo upload
```

批量清理命令会删除未跟踪文件并丢弃修改，只适合确认可重置的编译环境。
